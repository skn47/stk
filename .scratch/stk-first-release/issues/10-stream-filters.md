# 10: Stream filters — `stk log` / `stk err` / `stk summary` / `stk diff` / `stk json`

**What to build:** `stk log`, `stk err`, `stk summary`, `stk diff`, and `stk json` as native, `Budget`-aware filters over piped or command text, distinct from `rtk`'s tool-wrapping versions of the same names.

**Blocked by:** 06

**Status:** done

- [x] Each of `log`, `err`, `summary`, `diff`, `json` accepts stdin (and/or a command to run, consistent with the other verbs' capture conventions) and renders `Budget`-bounded output.
- [x] `err` isolates errors/warnings from mixed output; `summary` produces a heuristic condensed summary; `log` filters/deduplicates; `diff` condenses to changed lines/hunks; `json` compacts values (or keys-only, matching the documented flag).
- [x] All five are stateless in this release (no `Session`-aware behavior).
- [x] Fixture-driven tests cover at least one representative case per filter.

**Implementation notes:**
- `log` runs stdin through the existing `compression::compress_stdin` pipeline with the generic `relevance::classify` classifier — no new plumbing needed. `err` and `summary` execute a command via `CommandExecutor` and reuse `fastpath::lines_from` + `relevance::classify`; `err` hard-filters to `Error`/`Warning` chunks (matching real `rtk err`'s behavior, verified against the installed binary), while `summary` produces a heuristic one-line count plus the first error line. `diff` condenses already-diff-formatted text to `diff --git`/`@@` headers and `+`/`-` changed lines — not a two-file diff generator. `json` compacts via `serde_json` round-tripping, with `--keys-only` recursively nulling leaf values.
- All five share the new `verbs::filesystem_budget::render_optionally_budgeted` helper (None → join everything; `Some(budget)` → `truncate_sequential` with a clear stderr error + exit 2 if the budget is below the marker floor), which also replaced the previously-duplicated budget-dispatch blocks in `grep`/`find` from ticket 09.
- Code review caught and fixed 7 issues: `stk diff -` wasn't actually reading stdin (only branched on `Some`/`None`, never checked for the `-` sentinel — reproduced and fixed by matching `Some(path) if path != "-"`); `json`'s re-serialization used `.expect(...)`, a panic risk in a dispatch path — replaced with a proper `Result` match and stderr message; `diff`'s original line-classifier used a stateless prefix check (`starts_with("--- ")`/`"+++ "`) to detect file headers, which collided with real changed-content lines that happen to start the same way (e.g. a removed line whose text is "-- note" renders as "--- note" once the diff marker is prepended) — reproduced with such a case (both lines silently dropped) and fixed with a stateful `condense()` that tracks whether we're still in a file's header preamble, only treating `---`/`+++` as headers there; an over-long doc comment in `diff.rs` trimmed to 2 lines; the head/tail binary-search loop was duplicated between `truncate_head_tail` and `truncate_chars_head_tail` in `filesystem_budget.rs` — extracted into a shared `largest_k_that_fits` helper; the "None → join, Some → truncate_sequential + error" pattern was independently duplicated across `grep`/`find`/`diff`/`err`/`summary` — extracted into `render_optionally_budgeted`; and `Cargo.toml` had `serde` (with its `derive` feature) in `[dependencies]` for `serde_json::Value` usage, pulling `serde_derive`/`syn`/`quote`/`proc-macro2` into every production build even though only test fixture code needs the derive — moved back to `[dev-dependencies]`, since `serde_json` pulls in `serde_core` transitively without it.
