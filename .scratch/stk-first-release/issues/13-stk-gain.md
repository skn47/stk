# 13: `stk gain` — savings summary/history

**What to build:** `stk gain [-p] [-H] [-g] [-q] [-t TIER] [-d|-w|-m|-a] [-f FORMAT] [-F] [--reset]` shows a token-savings summary/history, matching the documented subset of `rtk gain`'s flags. This requires wiring lightweight savings-recording into `compile`, the two `Specialist`s, and the filters delivered so far, so there's real data to summarize.

**Blocked by:** 06, 07, 08, 09, 10

**Status:** done

- [x] `compile` (ticket 06), the Cargo/Git `Specialist`s (07/08), and the filters (09/10) each record their input/output token counts to a local savings-history store as they run.
- [x] `stk gain` (no flags) prints an overall savings summary (input tokens, output tokens, reduction).
- [x] History/tier/date-range flags (`-H`, `-t TIER`, `-d|-w|-m|-a`) filter or window the summary as documented.
- [x] `-f FORMAT` changes output format; `--reset` clears recorded history.
- [x] A golden-comparison test confirms `stk gain`'s output shape is compatible with the documented `rtk gain` flag subset (skipped gracefully without `rtk`).

**Implementation notes:**
- `UsageEntry` (already the shared `HistoryStore` seam `stk proxy` used) gained `input_tokens`/`output_tokens`/`cwd` fields, plus `HistoryStore::read_all`/`reset`. This reuses the existing seam already threaded through `cli::run` rather than adding a second one -- no new top-level dependency, no `cli::run` signature change. A new `history::record_savings(history, counter, verb, command, args, input, output)` helper is the one place every compressing verb reports its savings.
- Recording is wired into three shared choke points plus two standalone verbs: `compression::execute_and_compress`/`compress_stdin` (covers `compile` and both Cargo/Git `Specialist` dispatch), `filesystem_budget::render_optionally_budgeted` (covers `grep`/`find`/`diff`/`err`/`summary`), and direct calls in `read.rs`/`json.rs`. For `err`/`summary`/`diff`, "input" is deliberately the *un-filtered/un-summarized/un-condensed* raw text those verbs started from, not their already-reduced candidate list -- otherwise their recorded savings would only reflect a final budget trim, missing the verb's own real compression (e.g. `summary`'s whole job is condensing thousands of lines to one; using its own output as "input" would report near-zero savings for the verb that saves the most).
- `-p` (project scope) is real, not an inert flag: each recorded entry stores the cwd it ran from, and `-p` filters to entries matching the current cwd.
- `-d`/`-w`/`-m`/`-a` render additional breakdown tables (grouped by day/week/month via a small pure Howard Hinnant civil-date conversion, no date/time dependency needed) alongside the always-shown overall summary -- verified against the real installed `rtk`, whose own `-d`/`-w`/`-m` output is likewise a per-bucket breakdown table (its own "TOTAL" row matches the overall summary numbers, it doesn't restrict them). `-t TIER`/`-q` render a heuristic, clearly-labeled monthly quota estimate; `-F` prints a standalone message (STK's Specialists have no raw-execution fallback path to report on); `--reset` clears the store.
- Entries with no token counts (e.g. `stk proxy`'s plain usage-tracking entries) are excluded from every summary -- `gain` only ever summarizes verbs that actually compress something.
- Tests: `history.rs` covers the line format round-trip (including malformed-line resilience) and `record_savings`; `gain.rs` covers date-bucketing math and the full dispatch (summary math, all three formats, reset, project-scope filtering, CSV escaping); `tests/gain_verb.rs` covers the full recording pipeline end-to-end in-process (a compressing verb's savings actually reaching `gain`; a non-compressing verb's usage not counting), a real `FileHistoryStore`-backed run across two separate process invocations sharing `HOME`, and a golden-comparison test asserting every flag in the documented subset is accepted by both `stk gain` and (skipped gracefully without it) the real `rtk gain`.
- Code review caught and fixed 3 issues: CSV rows built via unescaped string interpolation, corrupting a row whenever a recorded command/argument contained a comma or quote -- fixed with proper CSV field quoting; `read.rs`'s no-budget path cloned the entire file content solely to unify the branch types -- replaced with `Cow<str>` so the common (no-budget) case borrows instead of copying; and a comment in `compression.rs` grown to 4 lines, trimmed back to 3. One finding was deliberately not acted on: `UsageEntry.command`'s empty-string sentinel for "no subprocess" (used by `read`/`grep`/`find`/`json`) was flagged as less type-safe than `Option<String>` -- true, but changing it would ripple through every recording call site and the on-disk line format for a stylistic gain with no correctness fix, so it was left as-is.
