# 06: `Budget`-bounded `stk compile` — `Chunk` model + Hard Budget Invariant + omission markers

**What to build:** `stk --budget N compile` adds the `Chunk` model and the full Budget Selection Algorithm on top of ticket 05's fast path: chunks are classified by priority (P0 fatal errors down to P5 noise), P0 is always included (structurally shrunk with a visible truncation marker if it alone exceeds budget), optional chunks are packed by score into whatever budget remains, and a final render-and-recount pass trims further if needed. Omission markers are themselves `Chunk`s (`ChunkKind::OmissionMarker`, ADR-0001), going through the same selection/accounting path as everything else. A `--budget` below the minimum viable floor is a clear refusal, not a degenerate render.

**Blocked by:** 05

**Status:** done

- [x] `Chunk { id, kind, text, source, token_count, score, priority, relationships }` and `ChunkKind` (including `OmissionMarker`) exist and are populated from ticket 05's fast-path output. A new `fastpath::lines_from` exposes the line-sequence stage both the unbounded and budgeted paths share. Generic (no-Specialist) classification is keyword-based: `error`/`panic`/`fatal` → P0, `warning`/`warn:` → P2, an already-collapsed repeated-line marker → P5, everything else → P3.
- [x] `ApproximateCounter` implements `ceil(max(chars/3, words*1.4))` per ADR-0002, used for all budget accounting.
- [x] Chunks are selected per the Budget Selection Algorithm: P0 mandatory chunks always included, shrunk (via a counter-verified binary search, not a char-count guess) if they alone exceed budget minus marker reserve; optional chunks packed by score into remaining space. Selection runs jointly across stdout+stderr (one shared budget pool), then splits back out per-stream for rendering.
- [x] A final render-and-recount pass re-measures actual rendered output and drops lowest-scoring optional chunks (never marker/P0 text) if the render pass pushed over budget.
- [x] `--budget` values below `marker_reserve + min_p0_floor` are refused with a clear error rather than rendered. `--budget` is parsed as a global option (before the subcommand, matching `rtk`'s convention) alongside recognized-but-rejected `--intent`/`--explain`.
- [x] Removed content always leaves a visible omission marker, itself a selected `Chunk` (`ChunkKind::OmissionMarker`) counted against the same budget — per-stream, so stdout and stderr each get their own marker(s) when either has content shrunk or dropped.
- [x] Fixture-driven tests cover normal budgeted compression, P0-forced-to-shrink (`tests/fixtures/p0_shrink.toml`), and budget-below-floor-refused, via `tests/compile_verb.rs` spawning the real binary with `--budget`.

**Implementation notes:**
- Code review caught and fixed 5 issues: `marker_reserve` only budgeted for one shrink marker + one omission marker total, but each stream can independently need its own of each (up to 4) — spurious `BudgetError::Internal` on legitimate dual-stream input (reproduced, fixed by doubling the reserve, regression-tested); a budget-too-small/internal-error rejection was double-reported (the budget layer's specific message, then a generic "failed to write output" line for the same rejection) — fixed with a `WriteOutcome::AlreadyReported` variant; three `.partial_cmp().unwrap()` calls on chunk scores were a latent panic risk if a score were ever NaN, violating this repo's no-unwrap-in-dispatch-paths rule — replaced with `f32::total_cmp`; the P0-shrink truncation loop was O(n²) (re-scanning and re-counting on every 3-character decrement) — replaced with a counter-verified binary search; and several new doc comments exceeded the repo's 3-line/no-ticket-reference convention — trimmed.
- The original truncation approach (a one-shot `remaining*3`-chars guess) had a separate, more basic bug caught before review: `ceil(chars/3)` rounding meant the guess reliably cost one token more than budgeted, so truncation always fell through to a full drop instead of ever keeping partial content — fixed (before the binary-search rewrite above) by verifying against the real counter.
